# Analyse d'ergonomie de la console `/system` (lecture seule)

Date de l'analyse : 15 octobre 2026. Périmètre lu : `src/app/system/**` (layout, tableau de bord, comptes, restaurants et fiche, commandes et fiche, contenu/pages, bannières, médias, textes, paramètres, réinitialisation, audit, design, mises à jour, géographie, taxonomie, liste d'attente, mises en avant), `src/components/admin/*`, `src/lib/system-admin/permissions.ts` et `tableauDeBord.ts`, les migrations SQL concernées, `admin.css`, `console-b.css`, `fantaisie.css`, `design.css`. Rien n'a été exécuté ni rendu à l'écran : tout ce qui est visuel est déduit du code et marqué « à confirmer visuellement » quand c'est le cas. L'éditeur de pages à blocs (`src/components/studio/editeur/*`) n'a PAS été lu : à vérifier.

Légende des efforts : S = moins d'une journée, M = 1 à 3 jours, L = plus de 3 jours.

## 1. Écarts avec le modèle « Wix-like »

### 1.1 Barre latérale à deux niveaux repliable
- **Existe** : `AdminNav.tsx:28-103` fait un accordéon à deux niveaux (famille = bouton `aria-expanded`, sous-entrées dans un tiroir). La famille courante s'ouvre toute seule (`:58-59`), le choix manuel l'emporte (`:31-39`). Filtrage par permission côté serveur (`groupesNavPourRole`). Tiroir mobile en `<dialog>` natif (`AdminMenuMobile.tsx:30-48`), fermé au changement de page (`:15-17`). Lien d'évitement (`layout.tsx:69`).
- **Manque** : repli de toute la barre en rail d'icônes ; mémoire de l'état ouvert/fermé (l'état est local au composant et perdu à chaque rechargement complet) ; icônes et compteurs (à valider : 3 restaurants, 2 commandes en attente) sur les entrées ; favoris/épinglés ; familles à entrée unique (Commandes, Audit) qui imposent un clic d'ouverture pour rien ; le survol ouvre les tiroirs (`admin.css:146-155`) ce qui entre en conflit avec le clic (voir problème P-09).
- **Effort** : M (rail + persistance cookie ou `localStorage` + badges ; le badge exige une lecture serveur par permission).

### 1.2 Recherche globale type Ctrl+K
- **Existe** : rien de global. Trois recherches locales par formulaire GET : e-mail (`acces/comptes/page.tsx:108-117`), restaurant (`restaurants/page.tsx:51-60`), référence de commande (`commandes/page.tsx:67-78`). Aucun gestionnaire clavier dans `src/components/admin` (recherche `keydown|ctrl|metaKey` : aucun résultat applicatif).
- **Manque** : une palette de commandes (dialogue + liste filtrable) ; index des destinations (réutilisable tel quel depuis `GROUPES_SYSTEME`, `permissions.ts:172-223`, déjà filtrable par rôle) ; recherche d'entités (restaurants, commandes, comptes) via une action serveur qui revérifie la permission de chaque type ; raccourcis d'action (« Créer une page », « Valider un restaurant » : déjà calculés dans `system/page.tsx:137-156`).
- **Effort** : M pour navigation + actions seulement ; L avec recherche d'entités (index, limites de résultats, audit de ce qui est consulté, prudence sur les coordonnées clients).

### 1.3 Accueil « prochaines étapes » avec checklist
- **Existe** : `FilePrioritaire.tsx` (« À traiter » : restaurants à valider, propositions client) et une ligne de raccourcis (`system/page.tsx:184-195`). C'est une file de travail, pas un parcours de démarrage.
- **Manque** : checklist de mise en service calculée sur les données (WhatsApp d'assistance renseigné, délai de validation annoncé, premier restaurant publié, couverture de communes, textes d'accueil personnalisés, double authentification activée, etc.), avec progression et possibilité de masquer ; les éléments existent déjà dans `parametres` et `stats`.
- **Effort** : M (liste d'étapes déclarative + état « masquée » persisté par utilisateur : `localStorage` pour un MVP, table sinon).

### 1.4 Tiroirs latéraux d'édition
- **Existe** : seulement des fenêtres modales centrées (`.ad-dialogue`) pour suppression de compte (`SuppressionCompte.tsx:42`), suppression groupée (`SelectionGroupee.tsx:87`), correction/suspension d'un restaurant (`ActionsModeration.tsx:135,167`) et le tiroir de navigation mobile. Les éditions se font soit en ligne dans la liste (taxonomie, géographie, mises en avant), soit sur une page dédiée (page, restaurant).
- **Manque** : un composant `Tiroir` (dialogue ancré à droite, URL ou paramètre `?editer=<id>` pour garder la liste en contexte), puis migration des éditions (restaurant : quartier, horaires, profil ; page ; bannière ; taxonomie ; mise en avant). Les formulaires existent déjà comme composants client réutilisables.
- **Effort** : M pour le composant ; L pour migrer les écrans (routes parallèles/interceptées de Next 16 ou paramètre d'URL, gestion du focus, de l'état « modifié » et de la fermeture).

### 1.5 Listes puissantes (colonnes configurables, filtres enregistrés, sélection multiple)
- **Existe** : filtres par puces pilotés par l'URL (restaurants, commandes, comptes, pages, bannières), recherche texte, tableau qui devient cartes sur téléphone (`admin.css:814-867`), lien étendu sur toute la ligne (`admin.css:778-783`), sélection multiple **uniquement sur les comptes et uniquement pour supprimer** (`SelectionGroupee.tsx`).
- **Manque** : tri, pagination (aucune ; `journalAudit.ts:36` plafonne en silence à 200 lignes ; l'annuaire a un drapeau `tronque`, pas les autres), colonnes configurables, vues/filtres enregistrés, actions groupées génériques (activer, publier, exporter), compteur total vs affiché, densité. La sélection actuelle repose sur des événements `document` et `querySelectorAll` (`SelectionGroupee.tsx:8-30,65-69`) : non réutilisable.
- **Effort** : L (composant `ListeDonnees` serveur+client avec état d'URL pour tri/filtres/page, préférences de colonnes en `localStorage`, vues enregistrées en base = migration + RLS + `get_advisors`).

### 1.6 États vides utiles
- **Existe** : `EtatVide` (`blocs.tsx:103-113`, titre + texte + icône), utilisé sur 11 pages ; certains textes guident (liste d'attente, couverture, pages).
- **Manque** : un emplacement d'action (bouton « Créer… ») ; la distinction « rien n'existe encore » / « aucun résultat pour ce filtre » (comptes `page.tsx:155` et restaurants `:83` disent la même chose dans les deux cas) ; lien « effacer les filtres ». Les bannières et médias utilisent un `Card` à texte nu (`bannieres/page.tsx:70-72`, `medias/page.tsx:34-37`), pas `EtatVide`.
- **Effort** : S.

### 1.7 Barre d'enregistrement unique
- **Existe** : `BarreEnregistrement` + `useSuiviModifications` (`BarreEnregistrement.tsx`) : détection de modification par sérialisation du formulaire, bouton Annuler, avertissement `beforeunload`, annonce lecteur d'écran, masquage au repos sur téléphone, confirmation 4 s. Composant de bonne qualité.
- **Manque** : il n'est utilisé que par `FormulaireParametres.tsx:263` (et le profil côté restaurateur). Tous les autres écrans ont leur propre bouton : textes (`GroupeTextes.tsx:118`), page (`EditeurPage.tsx:61`), profil restaurant (`EditeurProfilRestaurant.tsx:77`), taxonomie (`ListeTaxonomie.tsx:69`), un « Enregistrer » par jeton de design (`EditeurJetons.tsx:441-448`), géographie par ligne (non lu en détail : à vérifier). `beforeunload` ne couvre pas la navigation interne par `<Link>` : un utilisateur qui clique dans le menu perd ses modifications sans avertissement.
- **Effort** : M (adapter les formulaires à `useActionState` + le hook ; prévoir une garde de navigation interne ; les écrans à lignes indépendantes — jetons, géographie — demandent une décision : enregistrement groupé ou sauvegarde automatique).

### 1.8 Aide contextuelle et fil d'Ariane
- **Existe** : lien « retour » dans `PageHeader` (`blocs.tsx:23-30`) sur 4 pages de détail seulement (`commandes/[id]:53`, `restaurants/[id]:163`, `pages/[id]:40`, `reinitialisation:27`) ; textes d'aide sous les champs (`.ad-aide-champ`), tiroir « Comment les accès sont-ils séparés ? » en pied de page (`layout.tsx:89-96`), `Volet` repliables.
- **Manque** : fil d'Ariane (Famille › Page › Élément) : trivial à dériver de `GROUPES_SYSTEME` + chemin + libellé dynamique ; panneau/pop-over d'aide par page ; liens vers la documentation ; glossaire (palier, habilitation, mise en avant…).
- **Effort** : S pour le fil d'Ariane ; M pour l'aide contextuelle (rédaction + composant + emplacement).

### 2.1 Tableau de bord `/system` : ce qu'il affiche, est-ce actionnable ?

## 4. Accessibilité

À garder : lien d'évitement et `main tabIndex=-1` (`layout.tsx:69,83`) ; `aria-current` sur navigation et filtres ; `<caption class="sr-only">` sur les tableaux ; dialogues natifs (focus piégé, Échap) ; graphiques avec alternative textuelle et tableau de chiffres (`graphiques.tsx:66,139,193` ; `system/page.tsx:345-376`) ; pastilles toujours textuelles (`blocs.tsx:115`) ; région `role="status"` de la barre d'enregistrement ; lien de ligne étendu avec un seul lien pour le clavier (`admin.css:778-783`) ; tiroir replié en `visibility:hidden` (liens hors tabulation, `admin.css:133`).

Problèmes :
- **A-01 (moyen à grave) Contraste d'un texte** : `.dj-modifie` (« N modifications non enregistrées ») est en `var(--mangue)` (#FFC247) sur `var(--creme)` (#FFF6ED), soit environ 1,5:1 (calcul de luminance relative) pour un texte de 0,85 rem (`design.css:57-65`). Le contour encre épais du bouton atténue le problème mais ne remplace pas un anneau.

À confirmer visuellement.
- **A-04 (moyen) Cibles tactiles** : les boutons de famille de la navigation (`.ad-nav-titre`, `admin.css:94-111`) font environ 28 px de haut (padding 6 px, texte 0,68 rem) y compris dans le tiroir mobile ; les onglets de l'éditeur de design `.dj-groupe` (`design.css:40-49`, padding 4 px) idem. ## 7. Dette technique pour une refonte

- **CSS entièrement global et dépendant de l'ordre** : `src/app/layout.tsx:5-31` importe 27 feuilles pour toute l'application (public, restaurateur, console). Pour la console, l'ordre admin.css → console.css → console-b.css → fantaisie.css (`layout.tsx:21-25`) fait gagner la dernière : `console-b.css` « ne fait que redéfinir » `admin.css` (son en-tête, lignes 6-7). Résultat : le style d'un même composant est réparti sur 2 à 4 fichiers (ex. bouton : `components.css:10-59` + `controles.css:35` + `public-pages.css:588` + `console-b.css:56-89`). Changer un composant exige de lire les trois.
- **`.ad-app` est partagé avec la console restaurateur** (`rc-*` stylés dans `.ad-app`, `console-b.css:1-2`, `148`, `180-187`, `fantaisie.css:262-274`). Toute refonte de `.ad-app` touche aussi `/restaurant`. Introduire un conteneur propre à la nouvelle console (`.sx-app` ou `[data-console="system"]`) et ne pas modifier `.ad-app`.
- **Classes génériques re-stylées** : `.btn`, `.card`, `.field`, `.chip`, `.alerte`, `.badge`, `.lien-texte`, `.case-parametre` sont définies pour le site public (`components.css`, `controles.css`, `decouverte-b.css`) puis réhabillées sous `.ad-app` (`console-b.css:35-125,238-262`). Ajouter un composant qui emploie `.card` ou `.field` en hérite (bordure 2,5 px, ombre). Cas déjà vécu : `choix-carte` (CLAUDE.md). Cas actuel : `btn-secondaire` inexistant (P-13).
- **Règles sans exclusion** : `console-b.css:98-102` (focus des champs) touche les cases ; `fantaisie.css:254-260` (`label:has(> input[checkbox|radio])`) force `display:flex; min-height:44px` sur tout libellé qui enveloppe une case, hors `.option-supplement`/`.choix-carte` : un nouveau composant avec case dans un libellé sera réaligné sans prévenir ; `console-b.css:194-207` anime tous les enfants directs de `.ad-contenu` et des grilles (une liste générée dynamiquement rejoue l'animation à chaque rendu).

Plus lourds : `commandes/[id]/page.tsx` 13, `taxonomie/ListeTaxonomie.tsx` 11, `acces/comptes/page.tsx` 10, `system/page.tsx` 8, `SelectionGroupee.tsx` 7, `medias/page.tsx` 7, `EditeurPage.tsx` 7. Motifs répétés : `display:grid; gap; justifyItems:start`, `display:flex; gap:8`, `margin:0; color: var(--secondaire)`.
